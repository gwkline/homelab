# Factory Reclaimer Loop — Implementation Record

Implemented on branch `reclaim-loop`.

## Root cause found

The factory control plane was healthy but the work plane was not:

- launchpad orchestrator CronJobs completed every 10 minutes and logged `nothing queued`.
- `gwkline/launchpad` had 7 open `factory/failed` issues and no queued/in-progress work.
- Failed worker runs used the stale worker digest `8ecbd096…`, which predated the merged `skills-lib.sh` executable-bit fix (`5112a8a`). Logs showed `cannot exec '/tmp/tmp…': Permission denied` during private-skills sync; launchpad also hit unavailable crates.io/network and agent permission failures.
- The dashboard only surfaced queued/running/draft counts, hiding the 7 failed issues.

## Changes

- Added `apps/factory/orchestrator/run-reclaimer.sh`.
  - GitHub-only, fail-closed reads.
  - One issue per tick.
  - Requeues failures from the known-bad worker era once the fixed worker is available.
  - Retries cooled-down failures within a bounded attempt count.
  - Parks exhausted/open-PR cases as `factory/stuck`.
  - Avoids pipeline subshell state loss and unsafe marker word-splitting.
- Added offline fixture test `apps/factory/orchestrator/tests/reclaimer.test.sh`.
- Added hourly `factory-reclaimer` CronJob with `Forbid`, 15-minute deadline, backoff 0, TTL cleanup, no Kubernetes API access, and the existing orchestrator image.
- Copied the reclaimer into the orchestrator image and registered the manifest in Kustomize.
- Added `factory/stuck` to collector's terminal-label skip list and extended collector fixture coverage.
- Bumped both worker image pins to `sha256:0948d820…`, the image tagged `sha-9e31939` built after `5112a8a`.
- Added failed/stuck counts to the factory health API and dashboard subtitle so failed work cannot appear as an empty queue.
- Added CI execution for the reclaimer fixture.
